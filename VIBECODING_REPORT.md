# Отчёт по вайбкодингу

Как прототип Semantic TextNavigator создавался с помощью ИИ-инструментов. Подробный журнал по итерациям — в [`docs/PLAN.md`](docs/PLAN.md#журнал-ии-разработки).

## Инструменты

Claude Code в десктопном приложении (модель Claude Opus 5.5):
- режим планирования;
- навыки superpowers: brainstorming, test-driven-development;
- рекомендации по дизайну интерфейса;
- встроенный браузер для проверки интерфейса и деплоя.

Тесты — pytest и Streamlit AppTest, линтер — ruff, версии — Git и GitHub, публикация — Streamlit Community Cloud. LLM внутри приложения нет.

## Процесс

1. **План.** ИИ изучил PRD, документы и окружение и сам нашёл риск: локально установлен Python 3.15, которого нет в Streamlit Community Cloud. Поэтому выбран Python 3.12 и полный пиннинг зависимостей. ИИ предложил архитектуру и итерации и задал 4 вопроса: процесс Git, отображение недействующего договора, язык кода и документов, проверка расширяемости.
2. **Ревью плана человеком.** 6 корректировок:
   - нераспознанное изменение в действующем ДС → «Требует проверки»;
   - подписанное, но не вступившее в силу ДС — отдельный статус;
   - дата вступления договора в силу;
   - противоречие «тип ↔ статус подписи»;
   - состав README;
   - воспроизводимость окружения.

   Затем заказчик прислал текст задания, и в план добавились 4 вопроса пользователя и репетиция встречи.
3. **Итерации 0–8.** Каждая шла по TDD: сначала падающий тест, затем код. Итерация закрывалась после `pytest`, `ruff`, обновления документации, строки в журнале, коммита и push. Интерфейсные итерации дополнительно проверялись в браузере, в том числе на мобильной ширине.
4. **Деплой.** Вход в Streamlit Community Cloud и доступ к GitHub выполнил заказчик. Форму деплоя заполнил ИИ, публикацию заказчик подтвердил явно. Оказалось, что Cloud предлагает Python 3.11–3.14 и по умолчанию 3.14, а не 3.12, как писала документация на этапе плана. Версия 3.12 выбрана вручную.
5. **Сокращение README.** По просьбе заказчика README превращён в двухстраничную записку. Этот отчёт вынесен в отдельный файл, прежняя версия сохранена как [`old_README.md`](old_README.md).

## Роли

- **Человек:** требования (PRD, задание), утверждение плана, продуктовые решения, Git-идентичность, вход в Streamlit Community Cloud и разрешение на публикацию.
- **ИИ:** архитектура, код, тесты, документация, самопроверка, ручные прогоны на исходных файлах, проверка в браузере, заполнение формы деплоя.

## Ошибки ИИ и как их поймали

| Что было не так | Как поймали |
|---|---|
| В первой версии плана не были учтены четыре сценария бизнес-логики (см. корректировки выше) | ревью плана человеком |
| Глагол «переносится» не распознавался как изменение; «Договор поставки действует до 31.12.2026» уверенно принимался за срок поставки | сниппет-тесты |
| У договора, который не действует на дату, поле «действующее значение» содержало значения из текста | ручной прогон на трёх датах проверки → отдельное состояние «не действует» |
| Значения из `documents/` (даты, суммы, номер договора) в комментариях и docstrings — три раза за проект | тест-страж `test_no_hardcode.py` |
| При записи файлов `\u00a0` превращался в невидимый символ прямо в исходниках | ручная проверка байтов → тест-страж |
| Интерактивная таблица обрезала предупреждения; суммы переносились на мобильной ширине; CSS `nowrap` не действовал; просмотрщик оказывался вне экрана | проверка во встроенном браузере |
| Очищенная дата проверки роняла страницу | тест AppTest на итерации 8 |
| `components.html` устарел в Streamlit 1.67 | чтение документации установленной версии → `st.iframe` с экранированием |
| В отчёте неверно посчитаны тесты (192 модульных вместо 225) | самопроверка суммой по файлам перед коммитом |
| После деплоя в отчёте осталось устаревшее утверждение, что Cloud по умолчанию использует Python 3.12 | ИИ заметил при выводе README по просьбе заказчика |

## Что проверялось вручную

- Разбиение на абзацы, метаданные, значения и цитаты на 6 исходных файлах после каждой итерации ядра.
- Расчёт на 10.03, 28.02 и 07.02.2026.
- Интерфейс в браузере:
  - таблица и фильтр «раньше 01.04.2026»;
  - переходы к абзацам;
  - загрузка файлов через поле загрузки под произвольными именами;
  - удаление договора из набора;
  - мобильная ширина.
- Установка из чистого клона по README.
- Опубликованная версия в Streamlit Community Cloud: шесть исходных файлов загружены через поле загрузки, таблица, детали и просмотрщик совпали с локальной версией.

## Итог

288 автотестов:
- 225 модульных: разбор, примитивы, метаданные, условия, связывание, резолвер, просмотрщик;
- 21 приёмочный: PRD §4 и 4 вопроса задания;
- 17 на устойчивость, включая репетицию встречи (изменённое поле, новый договор того же формата);
- 3 теста-стража;
- 22 на интерфейс.

Итерации 0–7 по истории коммитов заняли около 1 ч 20 мин; планирование шло до первого коммита.

## Выводы

- **Ревью плана человеком окупилось сильнее всего.** Четыре из шести корректировок изменили бизнес-логику, и исправлять её потом было бы дороже.
- **Тесты-стражи нужны** именно потому, что ИИ склонен брать примеры из данных задачи — даже в комментариях.
- **Интерфейс без визуальной проверки не готов.** Пять проблем нашлись только в браузере, а загрузку файлов AppTest вообще не проверяет.
- **Консервативные правила хорошо сочетаются с ИИ-разработкой.** Принцип «лучше "Требует проверки", чем догадка» приводит к тому, что ошибка в правиле чаще даёт лишнюю проверку, чем неверное значение.
- **Факты об окружении проверяются на месте.** Документация на этапе плана и реальный Cloud разошлись в версии Python по умолчанию.
